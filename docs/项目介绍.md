# 论语 · 企业级研发流水线

**一句话**：让 AI 按正规企业研发流程帮你写代码——不只写代码，还管需求、评审、测试、版本、缺陷、复盘、日报周报。

## 它解决什么问题

普通 AI 编码只做一件事：你说需求，它出代码。

但真实项目里，写完代码只是开始。真正的坑全在流程里：

- 需求没说清就动手，白写
- 方案只列技术栈，不知道为什么选它
- 「测试应该能通过」从没跑过
- 缺陷只在聊天里提，下个迭代就忘
- 版本没有存档，出问题回不去
- 上线了没有日志，出错只能等用户投诉
- 写完了就完事，没有日报、周报、项目总结

**论语把这套企业研发流程变成 AI 的内置习惯。** 它不替代你写代码，而是陪你走完整个迭代，每一步都有文档和脚本支撑。

## 它怎么工作

接到需求后，论语按 12 步推进，每一步产出可落盘的交付物：

```
合规筛查 → 需求澄清 → 范围评审 → 方案设计 → 开源预研 → 编码
  → 自测 → 代码评审 → 版本归档 → 风险评估 → 复盘 → 收尾
  → 周期性复盘（日报 / 周报 / 项目总结）
```

每一步对应一句《论语》作为判断准则，但**不堆文言、不装斯文**，只在拿不准时用它定方向。

## 核心亮点

### 1. 三通道机制（不把小事套成 12 步）

不是所有需求都走完整流程。`flow.py` 按改动规模自动判断：

| 通道 | 什么时候 | 走几步 |
|---|---|---|
| 快速 | ≤2 文件、≤50 行、纯文档/测试 | 5 步 |
| 标准 | 中等改动 | 8 步 |
| 完整 | 大改动 / 敏感路径（支付、认证、数据库） | 全 12 步 |

### 2. 分类日志系统（写软件自带）

`logkit.py` 一键生成日志模块（Python / TypeScript），解决排错最痛的问题：

- **按问题域分类**：出支付问题只看 `payment.log`
- **trace_id 全链路**：一次请求一个 ID，grep 就串起全部日志
- **严格分级**：DEBUG / INFO / WARN / ERROR / FATAL，不混用
- **结构化字段**：`log.info("退款", order_id=x, cost_ms=12)` 可聚合可查
- **耗时埋点**：慢操作自动升级告警

### 3. 提交前密钥扫描

`preflight.py` 在 commit 前拦下硬编码密钥（AWS/GitHub/Stripe/阿里云）、调试残留、大文件、.gitignore 缺项。人眼在 CR 里看不出来的，它替你扫。

### 4. 缺陷工单台账

`bug_ledger.py` 把缺陷变成可跟踪的工单：P0-P3 分级、状态流转、根因归类。`stats` 还能当 CI 门禁——有未关闭 P0/P1 就返回失败码。

### 5. 版本归档 + 回滚

`release_note.py` 一条命令生成版本记录、CHANGELOG、tag 和回滚预案。出问题知道怎么退、影响什么、怎么验证。

### 6. 项目总结 + 日报 + 周报（好记性不如烂笔头）

`report.py` 一键生成日报/周报/项目总结，自动汇总缺陷台账、版本存档、CHANGELOG——不用手动统计，报告存到 `.lunyu/reports/`，形成可追溯的「烂笔头」。

`report.py` 还支持**定时自动日报**：运行一次 `python scripts/scheduler.py install --time 18:00 --project ...`，每天 18:00 自动生成当日日报（Windows 计划任务 / Linux cron 均支持）。

### 7. 自动化打包测试发包（一条龙）

开源了风火轮音乐项目沉淀的实战脚本，全部脱敏、凭据走环境变量：

- `build_apk.sh` — Gradle 自动化打包 APK + 输出 md5
- `vm_test.sh` — Android 模拟器冒烟测试（安装/启动/截图/抓崩溃）
- `send_mail.py` — 带附件邮件发送（SMTP，授权码走环境变量）
- `release.py` — 双端发布 GitHub + Gitee Release/附件/update.json
- `github-publish.sh` — 一键建 GitHub 仓库并推送

### 8. 一键自更新 / 升级（zip 安装包也能升）

用 zip 安装包解压安装的用户，目录里没有 `.git`，`git pull` 根本用不了——`self_update.py` 走 HTTP 下载覆盖，**这类用户照样一条命令升级**：

```bash
python scripts/self_update.py            # 检查并升级
python scripts/self_update.py --check    # 只看有没有新版，不改文件
python scripts/self_update.py --yes      # 非交互直接升级
```

- 跨平台：Windows / macOS / Linux 全通，不依赖 `unzip` / `rsync` / `curl`
- 保留 `.lunyu/` 用户数据（缺陷台账、日报周报不会丢）
- 清理远端已删除的旧文件（`--no-prune` 可关闭）
- 多源回退（raw / CDN / API），可设 `LUNYU_MIRROR` 走镜像
- 远端不比本地新就不动，**不会降级**

### 9. 内置单元测试（改脚本不怕回归）

`tests/` 目录为全部 Python 脚本提供 130 个 `unittest` 用例（零依赖），覆盖通道判定、密钥扫描、缺陷台账、版本存档、日报/周报、定时任务、SMTP、双端发布。修改脚本后跑 `python tests/run_tests.py` 即可防回归——这次还真的抓出了 `report.py` 发版统计的一个 bug。

## 十分钟上手

```bash
# 1. 接到需求，先判通道
python scripts/flow.py

# 2. 写代码时接分类日志
python scripts/logkit.py init --lang python --dest ./src/logkit

# 3. 提交前扫密钥
python scripts/preflight.py

# 4. 登记缺陷 / 打版本
python scripts/bug_ledger.py add --title "空数组越界" --priority P1
python scripts/release_note.py tag --version 1.0.0 --summary "首个版本"

# 5. 写日报 / 周报 / 项目总结
python scripts/report.py daily --project "我的项目" --body "今天完成XX"
python scripts/report.py weekly --project "我的项目" --body "本周完成XX"
python scripts/report.py summary --project "我的项目 v1.0" --body "核心成果"

# 6. 注册每天 18:00 自动日报
python scripts/scheduler.py install --time 18:00 --project "C:/我的项目" --author "你"

# 7. 跑单元测试防回归
python tests/run_tests.py

# 8. 已安装用户自更新
bash scripts/self_update.sh
```

## 技术特点

- **零依赖**：15 个脚本全部用 Python 标准库 / Bash，不需要 `pip install`
- **零硬编码凭据**：GitHub PAT、Gitee token、SMTP 授权码全部走环境变量，脚本里没有任何账号信息
- **中文优先**：交付物、注释、模板全部中文
- **开源友好**：MIT 许可，可自由使用、修改、商用、分发
- **流程可裁剪**：demo、内部工具、生产服务按需取用
- **可测试**：130 个单元测试用例，改脚本后一键防回归
