## 反模式

- 需求没问清就开写
- 方案只列技术栈，不写为什么不用别的
- 「测试应该能通过」而不实际跑
- `git push --force` 到共享分支
- 缺陷修完不更新台账
- 复盘写成「本次顺利完成，无问题」
- 打 tag 前不检查工作区是否干净
- 把《论语》原文大段抄进交付物当装饰
- **小改动硬走 12 步流程**（用 `flow.py` 判通道）
- **只靠 CR 拦质量问题**（提交前先跑 `preflight.py`）
- **用 `print` / `console.log` 代替日志**（无级别、无分类、无 trace_id）
- **异常只记「失败」不记栈**（等于没记）
- **用户输错密码记 ERROR**（这是 WARN，错误分级一乱，error.log 就废了）
- **一次性改数据库结构**（回滚预案直接失效）
- **上线没告警，靠用户投诉发现问题**
- **P0 事故复盘追人**（下次就没人敢报）
- **拿「走快速通道」当借口跳过自测和扫描**（省的是文档，不是质量动作）
- **纸面调研**：看眼 README 就推荐，从不装一次跑一遍（众好之，必察焉）
- **调研完不回灌方案**（学而不思则罔，报告白写）
- **已知问题藏着不报**（过而不改，是谓过矣 —— 沉默的已知问题会变成别人的事故）
- **顺手重构把 PR 撑爆**（不在其位，不谋其政 —— 一个 PR 只解决一件事）
- **CR 用纯风格意见阻断合并**（君子和而不同 —— 对代码不对人）
- **缺陷关闭不填根因和回归用例**（不迁怒不贰过 —— 没有防复发证据，等于没修）
- **提交前扫描只在嘴上要求，从没装钩子**（靠自觉的机制等于没有机制）
- **关键决策只写在方案文档里**（版本一换就失传，同一个辩论反复重开）
- **周报把本周日报重抄一遍**（用 `report.py` 自动聚合）
