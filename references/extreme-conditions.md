# 极端条件验证清单

> **岁寒，然后知松柏之后凋也。** ——《论语·子罕》

功能测试验证的是「按预期走会怎样」，极端条件验证的是「不按预期走会不会炸」。
**空值、并发、超时只是入门三样**，真正让线上出事的往往不在这三样里。

## 核心原则

1. **没验证过的降级等于没有降级**。写了 `try/catch` 不叫降级，跑通才算。
2. **故障必须主动注入**，不能等它自己发生。等来的第一次就是事故。
3. **每个场景都要有「通过标准」**，没有标准的测试无法判定成败。

## 十类必测场景

### 1. 依赖服务异常

| 故障 | 怎么测 | 通过标准 |
|---|---|---|
| 依赖全挂 | 断网 / kill 依赖 / 指向黑洞地址 | 返回明确降级结果，不白屏、不 500 |
| 依赖超时 | mock 注入 `sleep 30s` | 在自身超时内返回，不拖垮线程池 |
| 慢响应（未超时） | 延迟 2s、5s 递增 | 有熔断/快速失败，响应不随依赖线性劣化 |
| 返回脏数据 | mock 返回 null、空串、乱码、超大 JSON、字段类型错 | 不崩溃、不写入脏数据，记录告警日志 |
| 部分实例故障 | 负载均衡下摘掉 1/3 实例 | 错误率不飙升，重试能打到健康实例 |

- 超时时间 < 上游超时时间（**超时逐层收敛，不能逐层放大**）
- 重试有上限 + 指数退避 + 抖动，无裸重试

### 2. 磁盘与文件系统

| 故障 | 怎么测 | 通过标准 |
|---|---|---|
| 磁盘满 | `fallocate` 造大文件填满分区 | 写入失败有明确报错，不丢已提交数据，无半截文件 |
| inode 耗尽 | 循环创建大量空文件占满 inode | 同上（**只监控容量不监控 inode 会漏**） |
| 写权限缺失 | `chmod 000` 目标目录后重启 | 报清晰错误，指明路径与所需权限 |
| 只读文件系统 | 挂 `ro` 重跑 | 只读模式可运行，或启动即失败，不运行时才崩 |
| I/O 变慢 | `dd` 压测或 cgroup 限速 | 有 I/O 超时，不无限阻塞 |

### 3. 大数据量

| 场景 | 怎么测 | 通过标准 |
|---|---|---|
| 单表百万行 | 造 100w 数据跑核心查询 | 走索引，`EXPLAIN` 无全表扫描，P95 在预算内 |
| 深分页 | `LIMIT 1000000, 20` | 不超时；或已改为游标/ID 分页 |
| 单条记录超大 | 单行 10MB 文本/JSON | 流式处理，内存不爆 |
| 大文件上传 | 接近上限的文件 + 超限 1 字节 | 入口即校验大小，不读进内存才判 |
| 批量操作 | 一次提交 1w 条 | 分批执行，有进度反馈，可中断可续跑 |
| 列表无过滤 | 不带任何筛选条件查全量 | 强制分页上限，不返回无限结果 |

- 所有列表接口都有默认分页，**没有「默认返回全部」的接口**

### 4. 弱网与断网

| 场景 | 怎么测 | 通过标准 |
|---|---|---|
| 弱网 | `tc qdisc` 限速 50kbps / 丢包 5% / 延迟 500ms | 有超时重试，UI 有加载态和失败态，不无限转圈 |
| 断网重连 | 操作中断网 30s 后恢复 | 可重试成功或明确提示，不产生重复提交 |
| 高抖动 | 延迟在 100ms~3s 间随机跳变 | 连接复用正常，不频繁重建连接 |
| 移动端专项 | 2G/3G、电梯地铁、飞行模式切换 | 首屏可渲染（骨架屏/缓存），不阻塞等网络 |

### 5. 时钟与时区

| 场景 | 怎么测 | 通过标准 |
|---|---|---|
| 时钟回拨 | `date -s` 往回调 1 小时 / 1 天 | 无负间隔、`NaN` 耗时；定时任务不重复或漏触发 |
| 时钟前跳 | 向前调 1 小时 | token、证书过期判定行为一致 |
| 时区错乱 | `TZ=UTC` / `TZ=Asia/Shanghai` / 容器未设 TZ | 显示正确不差 8 小时；**UTC 存储，展示层转换** |
| 跨天跨月 | 23:59:59 与月末最后一天跑日期逻辑 | 日报、账单、统计口径正确，无边界差一天 |

- 无 `System.currentTimeMillis()` 裸用做业务时间；测耗时用单调时钟

### 6. 重试、幂等与并发重复

- **重试风暴**：依赖超时后瞬间涌入大量请求 → QPS 放大有上限，不击穿限流
- **重复提交**：同一请求并发发 10 次 / 连点 5 次 → 只生效一次，不重复扣款或插入
- **消息重复消费**：同一条 MQ 消息投递 3 次 → 结果一致
- **并发写同一条**：两请求同时改同一资源 → 乐观锁/版本号，后者得到冲突提示，不静默覆盖
- 所有写接口都有幂等键（请求 ID 或业务唯一键），**并有唯一索引兜底**

### 7. 冷启动与资源紧张

| 场景 | 怎么测 | 通过标准 |
|---|---|---|
| 冷启动 | 清缓存、杀进程后首次启动 | 首帧/首请求在预算内，无阻塞主线程的大计算 |
| 首屏首帧 | 移动端冷启动计时到首帧 | 有明确预算（如 ≤2s），超出有可归因的耗时分布 |
| 内存紧张 | cgroup 限内存至正常值 50% | 降级或拒绝服务，**不 OOM 被杀后无声重启** |
| 低端设备 | 低配机型 / 低内存手机 | 可用（可降画质/降功能），不闪退 |
| CPU 抢占 | `stress` 打满 CPU | 关键请求仍在超时内完成，有优先级 |

- 内存受限时日志、缓存、队列都有上限，不无限增长

### 8. 权限与会话失效

- **token 过期**：操作中途到期 → 自动刷新重试一次，或跳登录保留现场，**不报未知错误**
- **token 被吊销 / 异地登录**：服务端强制下线 → 下一次请求立即感知并登出
- **权限被拒**：降权用户访问原有权接口 → 403 明确提示，**前后端都校验**
- **会话并发失效**：多标签页同时登出/切账号 → 状态同步，不出现串号数据

### 9. 进程被杀与恢复

- **`kill -9` 后重启** → 已确认数据不丢，未完成任务可恢复或标记失败，**不卡在「进行中」**
- **滚动发布中被杀** → 有 graceful shutdown 与 drain 期，进行中请求优雅退出
- **断电/崩溃重启** → 靠 WAL / 事务 / 临时文件+原子 rename 保证一致性
- **配置错误**（缺字段、类型错、越界）→ **启动即校验失败退出**，配置校验前移
- **灰度回滚**（灰度 5% → 回滚）→ 行为完全回到旧版，新旧版本数据读写兼容

## 故障注入速查

```bash
tc qdisc add dev eth0 root netem delay 500ms loss 5%   # 弱网
tc qdisc del dev eth0 root                             # 恢复
fallocate -l 100G /tmp/fill.img                        # 磁盘填满
for i in $(seq 1 200000); do touch /tmp/f/$i; done     # inode 耗尽
systemd-run --scope -p MemoryMax=512M ./app            # 内存限制
stress --cpu 8 --timeout 60s                           # CPU 打满
date -s "$(date -d '1 hour ago')"                      # 时钟回拨
kill -9 $(pidof app)                                   # 强杀进程
```

## 上线前最低自测清单

- [ ] 主依赖挂掉 → 降级生效，不雪崩
- [ ] 主依赖变慢 → 不拖垮自身（超时逐层收敛）
- [ ] 磁盘写满 → 报错清晰，不丢数据
- [ ] 百万行查询 → 走索引，无全表扫描
- [ ] 弱网（500ms + 5% 丢包）→ 可用或明确失败
- [ ] 时钟回拨 1 小时 → 无异常
- [ ] 重复提交 10 次 → 只生效一次
- [ ] 内存限半 → 降级不崩溃
- [ ] token 过期 → 刷新或登出，不报未知错误
- [ ] `kill -9` 重启 → 数据一致，无卡死任务
- [ ] 配置写错 → 启动即失败
- [ ] 灰度回滚 → 行为与数据都回到旧版

## 反模式

| 反模式 | 后果 |
|---|---|
| 降级只在代码里写了，从没演练 | 真出事时发现降级分支本身也有 bug |
| 超时配置所有层都一样 | 下游重试放大，上游已超时放弃，雪崩 |
| 只监控磁盘容量不监控 inode | 容量充足却写不进去 |
| 幂等只靠应用层判断 | 判断与写入之间仍有并发窗口，须唯一索引兜底 |
| 弱网测试只在办公室 WiFi | 真实用户场景从未覆盖 |
| 配置错误等运行时才暴露 | 上线即事故，且发布时才发现无法启动 |
| 极端场景测一次就完事 | 代码变更后回归失效，应固化成用例 |
